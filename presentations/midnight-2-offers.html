Midnight 2.x / Demo Stack

midnight-2-offers, component by component

One Docker Compose project where every lane of this work runs together. This deck walks the parts: what each one is, which repo it comes from, and how they connect.

The whole stack

./up.sh --all

One command brings everything up and blocks until it is genuinely usable. One command wipes it. Everything is dev-only, on a throwaway local chain.

[Sources] README.md, quickstart and stack table

Why it exists

The testing module for all of these projects

The problem

Every demo needs the same groundwork: a local Midnight chain, an indexer, a proof server, and wallets already holding NIGHT and DUST. Each demo was rebuilding that from scratch, and each one got it slightly wrong in its own way.

The answer

Publish the groundwork once, then run every project on top of it as an opt-in profile. Each component is pinned to an exact repo and ref, so when a project changes, this stack is where the change is exercised against everything else.

A profile is a compose fragment: core always, then evm, offerfiles, solver, frontend, aa as needed.

[Sources] README.md, "The stack"; compose/ profile fragments

Four layers, one compose network

midnightntwrk (upstream)

Component / wallets

Wallets that are already funded

The manifest

wallets/wallets.json lists every wallet, its seed, and all address forms. Addresses derive from seed plus network id only, so they survive a full reset.

The roster

Three genesis wallets funded from block zero (faucet, batcher, AA deploy) and three demo actors funded on demand by fund-wallet.sh. The console's relay and taker wallets fund themselves when the aa profile comes up.

Lace-importable

Lace takes a mnemonic, never a hex seed, so the demo wallets use repeated-word phrases that can be typed straight into its import screen. One of them turns out to be Midnight's own test wallet, already funded at genesis.

Dev-only, deliberately public

Every seed and mnemonic in the repo is public and controls value only on the local undeployed chain. Never reuse any of them anywhere else.

Component / evm

umbra-evm: Midnight behind Ethereum's interfaces

A read-only eth_* JSON-RPC server over the chain, from the Umbra Indexer lane of this work. Ethereum tooling reads Midnight state without knowing it is Midnight: eth_getLogs, eth_subscribe, blocks and transactions, chainId 2400.

  • HTTP on :8545, WebSocket subscriptions on :10021.
  • Indexes into the shared PostgreSQL (db umbra).
  • Read-only by design: it can never sign or submit.

Which repo

acedward/UmbraDB

Built from the JSON-RPC branch; the work lives in its own PR on that repo. The console's infrastructure tab probes it like every other component.

The Offer Files Module / offerfiles

The offer-files lane, split into real services

celestia
A one-container Celestia devnet: the shared DA namespace offers are published to, with a token script for its JSON-RPC on :26658.
offerfiles-deploy
A one-shot container. The offer-files contract deploys exactly once per stack; the address persists in a volume across restarts.
kernel
The Effectstream sync node for the offer book, on :9999, migrated from ledger v8 to v9 so it runs against the 2.x chain. From effectstream/zswap-offerfiles-kernel.
batcher
Its own container on :3334, restarting independently of the kernel. It pays for and submits what users cannot.

The v9 migration is what unblocked this whole lane: before it, the kernel pinned ledger v8 and could not speak to a 2.x chain.

The Account Abstraction Module / aa

Account abstraction: contracts plus an overlay

Manager + Minter

acedward/AA-midnight-evm-experiment-v3

The account-abstraction contracts, sha-pinned to main. Deployed once per stack by a one-shot container; the receipt lands in a volume. Key-breaking merges upstream mean a redeploy here, never a silent drift.

Its own proof server

midnightntwrk (upstream, experimental build)

The AA circuits prove through the experimental proof-server build, internal-only, separate from the kernel's.

The k=18 overlay, opt-in

acedward/AA-midnight-evm-experiment-minocrab

Set one variable and the headline execute circuit proves with the MinoCrab port's half-size key: 544 MiB instead of 1.14 GiB, about twice as fast. Equivalence-tested against the reference compiler, unaudited, dev chains only. This stack is exactly where an artifact like that gets exercised before anyone trusts it further.

Component / the console

One page that ties every piece together

On :10700, built in this repo. The headline tab is the Midnight-EVM [AA] Wallet: connect any injected EVM wallet and the Manager's read surface executes immediately for that address. A registered account gets its balances and three operations: withdraw, transfer, and publish a real MIP-0005 offer to the kernel.

  • The relay recovers the signer's key from each EIP-712 signature, proves execute, and submits: the browser never holds a Midnight key.
  • Shielded withdrawals go to any pasted mn_shield-addr; the address itself carries the recipient's keys.
  • An AA infra tab holds the plumbing: funding, faucet, mint-and-send, the accounts table.

The other tabs

  • The offer book with the solver's live feed embedded.
  • An infrastructure canvas probing every component of this deck.
  • The memo web app, embedded.
  • A pin table of every repo in the stack.

Operations

Up, verify, reset, twice per machine

# everything, blocking until usable
./up.sh --all

# exactly core + the named profiles
./up.sh --converge --with aa

# health + wallets + every profile that is up
./verify.sh

# a second full stack beside the first
./scripts/pick-ports.sh > .env.test
ENV_FILE=.env.test ./up.sh --all

# stop but keep the chain / full reset
./down.sh
./down.sh -v

Nothing dials a host port

Every internal edge runs on the compose network, so remapping the published ports cannot break the stack. That is what makes two copies on one machine possible.

Reset is a real reset

down.sh -v wipes every chain-keyed volume; wallet addresses survive because they derive from seeds, and the contracts simply redeploy on the next up.

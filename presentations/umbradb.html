Architecture

Where the modules go

A new feature fills a known slot; the core does not change.

Storage

One block, one atomic write

A crash never leaves partial data, and anyone can prove their copy matches another.

One transaction per block, in this order

01Write

  • Only finalized blocks are stored, so the database never rolls back.
  • One transaction per block, cursor included.
  • After a crash the database holds the last whole block, and a restart resumes there.

02Subset

  • Modules use a subset of PostgreSQL commands: the ones that give the same result everywhere.
  • Same results on PostgreSQL 18 and PGlite.
  • A table can opt out, and the hash records that it did.

03Verify

  • A digest per table, updated every block.
  • A checkpoint about once a day.
  • Two instances compare one contents hash.

Modules

How a module plugs in

A feature is a module, and the core checks that it fits before any block is written.

01Declare

  • An id and a version.
  • What it requires and what it provides.
  • Its tables, its migrations, and its callbacks on the points.

02Checked at startup

  • The requirement graph is resolved before any block.
  • A missing provider, a cycle or a duplicate route stops startup and names the reason.

03Configure

  • One typed TypeScript file.
  • A change applies from a future height.
  • One version of each module per build.

The core-* modules use the same API as yours.

Module API

A module in code

import { defineModule } from "umbradb"; import { z } from "zod"; export const specVersions = defineModule({ id: "spec-versions", version: "1.0.0", side: "public", requires: ["block-header"], // put by core-block-fetch provides: [{ name: "spec-versions", lifetimes: ["table"], table: { schema: "spec_versions", tables: ["rows"], kind: "append-only" }, }], startsMidChain: true, configSchema: z.object({}), migrations: [{ id: "001", sql: `CREATE TABLE spec_versions.rows (height bigint PRIMARY KEY, spec int NOT NULL)` }], points: { async "on-db-write"(_p, b, w) { // inside the block's transaction const header = b.items.get("block-header") as { specVersion: number }; await w.execute("INSERT INTO spec_versions.rows VALUES ($1, $2)", [b.height, header.specVersion]); }, }, });
// umbradb.config.ts export default defineConfig({ entries: [ coreEntry({ start: 0, config: { network: "preprod", database: "pglite:memory", node: "ws://127.0.0.1:9944" } }), specVersions.entry({ start: 1_000_000, config: {} }), ], });
  • At startup: block-header has a provider, and the graph has no cycle.
  • The table follows the PostgreSQL subset.
  • It starts at height 1,000,000; earlier blocks are not touched.
  • Its table joins the digest from its first block.

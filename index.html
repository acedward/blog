Offer Files

Depends on Effectstream Improvements, UTXO Pinning, Proved Messages in ZSwaps · Needed by Intent Solver COW

A DEX built on offer files: instead of orders living in a contract, they're published as files to a shared Celestia DA namespace, where anyone can read them and try to match them. The node implementation is the Effectstream kernel.

This needs two things to exist together: the code and the spec. So alongside the kernel, there are two Midnight improvement proposals, one that generalizes offer files to full proven transactions, and one that defines the shared DA namespace they get published to. Both are implemented and both need revision.

  • core: zswap-offerfiles-kernel, Effectstream node implementation for a Midnight offer-files DEX through Celestia DA. Repo
  • mip-zswap-offer: MIP implementation, serialize, deserialize and validate zswap offers according to the proposed MIP specs. Repo
  • MIP-0005: Generalize offer files to full proven transactions, implemented, needs revision. Open. PR #227 · Repo
  • MIP-0006: Publish swap offers to a shared DA namespace, implemented, needs revision. Open. PR #228 · Repo

Umbra Indexer

Needed by Effectstream Improvements, Midnight <> EVM

UmbraDB is where Midnight chain data gets indexed and served. Most of the work here is about where the data actually comes from: the indexer sits between the node and everything downstream, so every assumption it makes about block format and sync behaviour eventually becomes someone else's bug.

Two directions so far. One is skipping the indexer entirely and reading straight from the node, which we built as a proof of concept to see what it costs. The other is keeping Umbra current with Midnight 2.x: a ledger-v9 decoder, archive sync fixes, and a wallet monitor. Beyond that, we still need to write down what a replacement indexer would actually have to do, and the JSON-RPC and get_logs interfaces still need a written spec.

  • Read from the node instead of the indexer, not merged, proof of concept. PR #1 · Repo
  • Update Umbra + Midnight 2.+, ledger-v9 decoder, archive sync fixes, wallet monitor plus evm_rpc schema, security-audit rounds. Open. PR #2 · Repo
  • Requirements for indexer replacement, not started yet. Repo
  • JSON-RPC and get_logs MIP spec, writing the interfaces down as a MIP. Not started yet. Repo

Midnight <> EVM

Depends on Umbra Indexer

The EVM has a decade of tooling built around a small number of interfaces: eth_getLogs, eth_subscribe, JSON-RPC, accounts. If Midnight speaks those interfaces, that tooling works without anyone porting it.

So we're building the translation layer in pieces: an account abstraction experiment, a mapping from Midnight contract events onto EVM logs (with an ingester and backfill so historical queries work too), and an eth_* JSON-RPC server on top of UmbraDB. The second pass at account abstraction widens the aim: rather than supporting a wallet's erc20.transfer(...), use EVM signatures to authorise generic trustless messaging.

  • Account abstraction on Midnight, an experiment bridging Midnight and the EVM. Repo
  • umbradb-evm-logs: contract events as EVM logs, event to log mapping, ingester, eth_getLogs / eth_subscribe, backfill. Open. PR #4 · Repo
  • umbradb-evm-rpc: eth_* JSON-RPC server, JSON-RPC server and methods, one squashed commit. Open. PR #3 · Repo
  • AA version 2, drops support for wallet erc20.transfer(...) so that EVM signatures can authorise more generic trustless messaging. Work in progress, no repo yet.

Effectstream Improvements

Depends on Umbra Indexer · Needed by Offer Files

Effectstream is the platform the rest of this work plugs into: chain sync, primitives, batchers, wallets, and starter templates. Adding a chain means teaching it that chain's primitives and how transactions get paid for there.

Improvements land wherever they're needed: infrastructure, support for a new chain, better Midnight support, a smaller starting template. None of it is one theme, so the list below is simply the current batch.

  • Project template: single page, a literal one-file Bun example that watches a Midnight counter and serves basic HTML. Open. PR #865 · Repo
  • Solana support, sync, primitives, gasless batcher, wallets and a starter template. Merged. PR #815 · Repo
  • Midnight 2.+ event support, adds a stagenet v2 contract template. Open. PR #860 · Repo
  • Multi batcher, one batcher process can serve many products. Open. PR #855 · Repo
  • Effectstream Docker image, versioned offline template runtime with system dependencies and binaries. Open. PR #867 · Repo
  • Faster startup on complex Midnight setups, speeds up Night-Bitcoin wallet launch with a prefunded genesis. Open. PR #857 · Repo
  • Docs for Midnight [DevRel], not started yet. Repo

Umbra + Effectstream

Effectstream has its own sync layer, and UmbraDB has the archives. Connecting the two means Effectstream can read Midnight primitives without running its own indexing stack.

The first primitive we went after is UnshieldedCreate, read from an unmodified Umbra archive, devnet only. That's as far as it goes for now: the rest is blocked until Umbra is extended to expose more data.

  • Fetch Midnight Primitive [UnshieldedCreate] from UmbraDB, devnet only, draft PR. Blocked on Umbra exposing more data. PR #866 · Repo

Proved Messages in ZSwaps

Needed by Offer Files

A ZSwap offer moves value but carries no message. Attaching a proved memo to an offer would let the sender say something alongside the swap, provably, without breaking the shielded model.

This touches two layers, so it's two experiments in parallel: one in the ledger, one in the node. Both are early.

  • midnight-ledger-zswap-memo, ledger-side experiment, work in progress. PR #5 · Repo
  • midnight-node-zswap-memo, node-side experiment, work in progress. PR #5 · Repo

Intent Solver COW

Depends on Offer Files

When two offers happen to want the opposite of each other, they can settle directly instead of going through a pool. Finding those coincidences of wants across the offer files is what the solver does. Work in progress.

  • Intent Solver COW, work in progress. PR #38 · Repo

Compile & Deploy Midnight Contracts (Web / WASM)

Compiling a Compact contract normally means installing a toolchain first. Ship the compiler as WebAssembly and the browser becomes the toolchain: write, compile and deploy a Midnight contract from a tab, with nothing installed locally. There's a live demo.

  • zkir-wasm-experiment, compile and deploy Midnight contracts in the browser (WASM). Live · Repo
  • Merge ZKIR fixes upstream, the changes ZKIR needed to build for the browser should land upstream instead of living here. Repo

Nix-Nax

A game on Midnight that is actually fast to play. Turns take a few milliseconds because they don't each wait for a block: only the initial and final settlement happen on chain. It's published and playable, but there are no docs yet.

  • nix-nax, published, no docs yet. Live · Repo
